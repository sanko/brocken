=head1 NAME

Brocken::Jenny::Lowerer::Wasm - WebAssembly Lowerer (Lindsay IR to MIR)

=head1 DESCRIPTION

Lowers Lindsay IR to machine-level MIR for WebAssembly. Translates SSA instructions to WASM-compatible operations.

=head2 Lowering Strategy

=over

=item B<Parameters> mapped to C<local.get> / C<local.set> by index (no physical registers)

=item B<Arithmetic> lowered to WASM i32/i64/f32/f64 opcodes directly

=item B<Boxing/Unboxing> packed into linear memory via C<i64.store> / C<i64.load>

=item B<Refcounting> uses C<i64.atomic.rmw> for atomic increment and
C<i64.atomic.rmw> + conditional free for decrement

=item B<Memory> uses WASM linear memory with explicit alignment (4 for i32, 8 for i64)

=back

=head2 Alloca

WebAssembly has no stack pointer, so C<alloca> cannot be a frame pointer bump. An C<alloca> whose element count is a
constant is instead allocated from Brocken::Runtime::bump_alloc, the same allocator objects and array slots come from,
which is what lets a slot escape its function.

That sharing is the point rather than a convenience. An earlier version gave escaping allocas their own copy of the
bump cursor while objects advanced the cursor inside the runtime header. Both started at the heap base, so the two
hands of the allocator could hand out the same bytes. Reading the base and letting the single allocator advance it
removes the second cursor.

A C<alloca> of a single scalar is further promoted to a WASM local where it does not escape, which avoids the
allocation entirely. A non-constant element count is rejected.
